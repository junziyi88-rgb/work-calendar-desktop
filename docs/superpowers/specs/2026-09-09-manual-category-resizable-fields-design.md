# 手动分类与可调输入框设计

## 目标

把分类从“自动/手动下拉选择”改成直接输入，并让系统从手动分类中学习，下一次填写相同工作内容时自动匹配。同时撤销整块页面模块缩放，仅允许实际可填写的文字输入区域调整大小。升级不得改变或删除现有事项、记录、分类和工时。

## 分类交互

- 新建记录与编辑记录中的“分类”改为文本输入框，已有分类名作为自动补全候选。
- 输入工作内容时，继续使用现有关键词规则实时匹配；匹配成功后自动在分类框中显示分类名。
- 用户改写分类框后视为手动分类。输入已有名称时复用该分类；输入新名称时自动创建分类。
- 手动分类保存成功后，把本次完整工作内容追加为该分类的关键词。这样从历史内容候选再次选择或输入包含该完整内容的文本时，会自动匹配分类。
- 自动学习使用完整工作内容，优先避免过宽关键词造成误分类。用户可以在现有分类管理中把关键词改短，以扩大匹配范围。
- 用户手动清空分类框时保存为“未分类”，不会强制套用当前自动建议。
- 编辑自动分类记录且未触碰分类框时，修改事项或内容会重新计算自动分类；触碰分类框后改为手动模式。

## 数据与兼容性

- 沿用数据库 schema v3，不删除或重建表。
- `WorkLogInput` 增加仅用于保存流程的 `categoryName` 字段；数据库中的记录仍保存 `category_id` 与 `category_mode`。
- 新分类使用现有分类表和默认柔和颜色；同名比较忽略首尾空格和大小写。
- 学习关键词时去重，保留已有人工维护关键词。
- 安装前复制最新数据库并校验哈希；安装后核对事项数、记录数和旧字段校验值。

## 可调输入区域

- 移除记录、事项、总结和分类管理外层模块的缩放容器与“复原”按钮。
- 可拖动调整的对象改为文字输入区域：关联事项、工作内容、工时、分类、新事项名称、分类名称和分类关键词，以及记录编辑器中的对应字段。
- 日期、时间、下拉选项和普通按钮维持固定尺寸，避免控件布局失控。
- 每个输入区域独立记忆宽高；设置合理最小尺寸并限制在所属表单范围内。
- 调整大小只写入浏览器本地界面存储，不影响业务数据库或导出内容。

## 验收标准

- 分类可直接输入，已有分类支持自动补全，新名称能随记录保存创建。
- 手动分类一次后，再填写相同历史工作内容可自动匹配该分类。
- 编辑记录时可改写或清空分类，并正确保持自动/手动模式。
- 页面模块不再整体缩放，文字输入区域可单独缩放并在重启后恢复尺寸。
- 升级前后的事项、记录、内容、工时和关联关系完全一致。
- 自动测试、类型检查、生产构建、安装和安装后数据核验全部通过。
