# 工作记录时间、历史内容与分类升级设计

## 目标

在不改变“记录、事项、总结”三页主结构的前提下，让工作记录具备准确时间、可完整编辑、历史内容复用、明确的总结选期和本地关键词分类，同时完整保留现有数据。

## 核心交互

### 新建记录

- 表单打开和每次保存后，日期与时间都读取当时的本地系统时间。
- 日期和时间可以手动修改。
- 日记录保存精确发生时间；周记录仍归属某一周，但也保存实际填写时刻。
- 工作内容输入框从所有未删除历史记录中生成去重候选，仍允许输入新内容。
- 系统根据“关联事项标题 + 工作内容”实时给出分类建议，用户可改选分类或选择“未分类”。

### 编辑记录

- 编辑器允许修改关联事项、工作内容、工时、日/周粒度、日期、时间和分类。
- 已完成事项仍可作为原记录的当前关联对象显示和保留；改选到其他事项时只显示可用事项。
- 手工改选分类后，该记录进入手动分类模式，后续修改内容不会覆盖用户选择。

### 历史内容与筛选

- 工作内容候选由未删除记录动态派生，不新增模板维护页面。
- 比较时忽略首尾空格和大小写，展示最近使用的写法。
- 记录页和总结页支持按关联事项、历史工作内容和分类筛选。
- 新内容保存后立即进入候选；没有记录继续使用某内容时，它自然从候选中消失。

### 总结选期

- 总结页增加日期选择器，并在周总结下展示当月日历。
- 点击任一天即可选择它所在的周或月；周视图突出周一至周日整行。
- 周标题使用“2026年第37周 · 9月7日—9月13日”，月标题使用“2026年9月”。
- “本期”改为“回到本周”或“回到本月”，前后按钮继续按周或月移动。

### 分类

- 分类字段包括名称、颜色、关键词列表；分类可新增、编辑和软删除。
- 自动分类同时匹配事项标题和工作内容，忽略大小写。
- 命中多个分类时，最长关键词优先；长度相同按分类创建顺序优先。
- 自动分类的记录在内容或关联事项改变时重新匹配。
- 手动分类是粘性的，不会被规则重新覆盖。
- 修改分类关键词后，仅重新计算自动或未分类记录，手动分类保持不变。
- 分类管理放在现有“更多操作”菜单的轻量面板中，不增加主导航。

## 数据模型与兼容性

- 数据库版本从 2 升到 3。
- `work_logs` 增加 `occurred_at`、`category_id`、`category_mode`。
- 新增 `categories` 表，包含 `id`、`name`、`color`、`keywords_json`、软删除和时间戳字段。
- 旧记录的 `occurred_at` 从 `created_at` 补齐；原有 `period_start`、内容、工时和事项关联不改变。
- 旧记录默认处于自动分类模式，但在用户创建规则前保持未分类。
- 迁移在事务中执行；升级启动前创建时间戳备份，失败时回滚并保留原数据库。
- 保持应用 `appId` 和 `%APPDATA%/work-calendar-desktop` 数据目录不变，安装升级不得清除用户数据。

## 视觉约束

- 延续现有暖灰、平面、低干扰的极简界面。
- 不增加主页面，不引入大面积颜色、渐变、重阴影或复杂动效。
- 分类颜色只用于小标签和筛选状态。
- 编辑器与日历采用紧凑展开区域，桌面窗口在 820px 最小宽度下仍可操作。

## 验收标准

- 新记录默认日期和时间与本地系统时间一致，且可修改。
- 已有记录的事项和内容均可编辑。
- 所有未删除历史工作内容可被搜索、复用和筛选。
- 总结页能通过日历准确定位任意周/月，并显示明确日期范围。
- 分类规则可维护、自动匹配且支持手工覆盖。
- 升级前后现有事项数、记录数、记录内容和工时一致。
- 自动测试、类型检查、生产构建和安装后数据核验全部通过。
