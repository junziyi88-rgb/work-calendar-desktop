# 事项分类与双入口编辑设计

## 目标

把分类的默认归属从单条工作记录提升到事项，同时保留单条记录覆盖分类的能力。自动分类只根据事项名称匹配关键词，不再读取或学习具体工作内容。事项名称可以从记录编辑器和事项详情页两个入口修改，修改后所有关联记录统一显示新名称。

升级必须保留现有事项、记录、分类、工时、日期和关联关系。

## 分类模型

- `work_items` 增加 `category_id` 与 `category_mode` 字段。
- `category_mode` 取值仍为 `auto` 或 `manual`：
  - `auto`：根据事项名称匹配分类关键词。
  - `manual`：使用用户为事项明确选择的分类，也允许明确设为未分类。
- `work_logs` 继续保留现有分类字段，用于记录实际分类和单条记录例外：
  - 自动记录默认继承所属事项当前分类。
  - 手动记录保留自己的分类，不随事项变化。
- 没有关联事项的记录不进行关键词自动分类，但仍可手动选择分类。

## 关键词匹配与学习

- 自动匹配的唯一输入是事项名称。
- 工作内容不再参与自动匹配，也不会被自动追加到分类关键词。
- 关键词使用包含匹配，忽略首尾空格和大小写；多个分类同时命中时，继续采用“较长关键词优先、分类创建时间优先”的现有规则。
- 用户在事项上手动选择分类后，将完整事项名称加入该分类关键词，重复值忽略。
- 用户重命名自动分类事项时，使用新名称重新匹配分类。
- 用户重命名手动分类事项时，保留原分类，并将新名称补充到该分类关键词；明确未分类的事项不学习关键词。
- 分类关键词被修改或分类被删除时，重新计算自动分类事项以及其未被手动覆盖的记录。

## 编辑交互

### 记录页

- 记录编辑器中的“关联事项”由只读选择器改为可输入、可选择的事项名称字段。
- 保存已有记录时，如果仍关联原事项但名称发生变化，则直接重命名原事项；所有关联记录随即显示新名称。
- 选择另一个已有事项时，仅改变该记录的关联事项，不重命名原事项。
- 输入一个不存在的事项名称时，新建事项并将该记录关联过去。
- 分类字段显示当前记录的实际分类。用户触碰分类字段后，该记录进入手动覆盖模式；可以选择其他分类或清空为未分类。
- 未触碰分类字段时，记录继承目标事项的分类。

### 事项页

- 事项详情页增加“编辑事项”入口。
- 可修改事项名称和默认分类，并在同一区域保存或取消。
- 自动分类状态下，分类框展示由事项名称得到的建议；用户改写或清空分类框后转为手动模式。
- 保存事项后，更新所有自动分类记录；手动覆盖记录保持原分类。

## 数据流与一致性

- `WorkItem` 与 `WorkItemInput` 增加分类字段。
- 保存事项时，存储事项分类并同步该事项下 `category_mode='auto'` 的记录。
- 保存记录时，先解析关联事项的选择、重命名或新建，再解析记录分类：未手动覆盖则继承事项分类，手动覆盖则使用记录输入。
- 分类筛选、统计与导出继续读取记录实际保存的 `category_id`，保证结果稳定。
- 事项名称只存储一份，记录列表通过 `workItemId` 读取，因此重命名后所有关联记录自动显示新名称。

## 数据库迁移

- schema 版本升级并为 `work_items` 添加可空的 `category_id` 和非空的 `category_mode`，默认 `auto`。
- 迁移现有数据时：
  - 按现有事项名称重新计算事项的自动分类。
  - 每个事项下的自动记录同步为事项分类。
  - 现有手动分类记录保持分类与模式不变。
  - 无关联事项的自动记录改为未分类。
- 不删除、重建或覆盖现有业务表和记录。

## 错误处理

- 空事项名称不能保存。
- 重命名、新建事项或保存分类失败时，记录编辑器保持打开并显示错误，不提交半成品记录。
- 数据库中的事项更新、关键词学习和自动记录同步在同一事务中完成，失败时整体回滚。
- 已完成事项仍可重命名；把记录改关联到另一个已完成事项时，沿用现有限制，要求先重新打开事项。

## 测试与验收

- 自动分类只匹配事项名称，工作内容即使命中关键词也不会分类。
- 事项手动分类后学习完整事项名称，不学习工作内容。
- 新记录默认继承事项分类。
- 单条记录手动改分类或清空后，不随事项分类变化。
- 在记录页重命名事项后，所有关联记录及事项页显示新名称。
- 在事项详情页可以修改事项名称和默认分类。
- 自动分类事项重命名后重新匹配；手动分类事项重命名后保留分类。
- 数据迁移保留事项、记录、工时、日期、内容、手动分类和关联关系。
- 单元测试、组件测试、类型检查和生产构建全部通过。
